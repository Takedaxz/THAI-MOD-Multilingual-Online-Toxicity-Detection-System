3. Problem Description 
แพลตฟอร์มโซเชียลมีเดียและเว็บบอร์ดออนไลน์ในประเทศไทย ประสบปัญหาการจัดการข้อความที่ไม่พึงประสงค์ในปริมาณมหาศาล เช่น การแสดงความเกลียดชัง การคุกคาม การใช้คำหยาบคาย และการกลั่นแกล้งบนโลกออนไลน์ ซึ่งส่งผลกระทบโดยตรงต่อสภาพจิตใจของผู้ใช้และชื่อเสียงของแพลตฟอร์ม อีกทั้งยังเสี่ยงต่อการละเมิดกฎหมายและแนวปฏิบัติด้านจริยธรรมที่เข้มงวดขึ้นในปัจจุบัน
ปัญหาหลักที่พบคือระบบจัดการเนื้อหาในปัจจุบันยังขาดประสิทธิภาพในด้านต่างๆ ดังนี้:
ข้อจำกัดด้านทรัพยากร: การพึ่งพาแรงงานมนุษย์เพียงอย่างเดียวมีต้นทุนที่สูงมาก มีความล่าช้าในการตรวจสอบ และไม่สามารถรองรับการขยายตัวของข้อมูลจำนวนมากได้อย่างมีประสิทธิภาพ
ความอ่อนไหวทางภาษา: โมเดลตรวจจับส่วนใหญ่ถูกฝึกฝนด้วยข้อมูลภาษาอังกฤษ จึงไม่สามารถเข้าใจบริบทของภาษาไทยที่มีความซับซ้อนสูง ทั้งในแง่ของวัฒนธรรม การตัดคำ คำแสลงเฉพาะกลุ่ม หรือการประชดประชัน ซึ่งทำให้การคัดกรองเกิดความผิดพลาดบ่อยครั้ง

4. Target Customers
ผู้ดูแลแพลตฟอร์มโซเชียลมีเดียและเว็บบอร์ด: กลุ่มที่ต้องการระบบอัตโนมัติมาช่วยลดภาระงานคัดกรอง เพื่อสร้างพื้นที่การสนทนาที่มีคุณภาพและรักษาฐานผู้ใช้งานในระยะยาว
ทีมกำกับดูแลความปลอดภัยและเนื้อหา: ทีมที่ต้องการเครื่องมือช่วยตัดสินใจที่แม่นยำ เพื่อจัดการกับเนื้อหาที่ละเมิดกฎระเบียบได้อย่างรวดเร็วและเป็นไปตามมาตรฐานสากล
ผู้พัฒนาแอปพลิเคชันหรือเว็บไซต์ที่มีเนื้อหาจากผู้ใช้: กลุ่มที่ต้องการระบบคัดกรองสำเร็จรูปไปติดตั้งในผลิตภัณฑ์ของตนเอง เพื่อป้องกันปัญหาการใช้ข้อความที่เป็นพิษตั้งแต่ต้นทาง
ผู้ใช้ทั่วไปและสังคมออนไลน์: กลุ่มบุคคลที่ต้องการสภาพแวดล้อมดิจิทัลที่ปลอดภัย ลดการเผชิญกับเนื้อหาที่บั่นทอนสุขภาพจิตและสร้างความแตกแยกในสังคม

6. Goals (4 Levels)
6.1 Business Goal
Brand Safety & Trust: เพื่อสร้างสภาพแวดล้อมที่ปลอดภัยและน่าใช้งาน ช่วยรักษาฐานผู้ใช้งานเดิมและดึงดูดผู้ใช้ใหม่ ลดความเสี่ยงที่แบรนด์จะเสียชื่อเสียงจากความขัดแย้งในคอมเมนต์ โดยมุ่งลด user report rate และเพิ่มความน่าเชื่อถือและความปลอดภัยของแพลตฟอร์มในระยะยาว
Operational Cost Reduction: ลดภาระค่าใช้จ่ายในการจ้างแรงงานมนุษย์ (Human Moderators) โดยการใช้ระบบอัตโนมัติคัดกรองเนื้อหาเบื้องต้นได้มากกว่า 80-90% ของปริมาณข้อความทั้งหมด เพื่อลดภาระงาน manual review
6.2 User Goal
Enhanced User Experience: ผู้ใช้ทั่วไปสามารถดูเนื้อหาและร่วมสนทนาได้อย่างสบายใจ ลดการเผชิญกับ Cyberbullying, Toxic Language และ Hate Speech
Moderator Well-being & Efficiency: ช่วยลดความเครียดสะสมของทีม Moderator ที่ต้องอ่านข้อความ Toxic ปริมาณมาก และเพิ่มความเร็วและคุณภาพในการตัดสินใจด้วยข้อมูลวิเคราะห์จาก AI
Transparency: ผู้ใช้รับทราบถึงมาตรฐานการจัดการเนื้อหาที่ชัดเจนและเป็นธรรม
6.3 System Goal
Near Real-time Processing: ระบบต้องสามารถประมวลผลและตอบกลับ (Inference) ได้ภายในเวลาที่เหมาะสมต่อการใช้งานจริง เพื่อให้การ Moderation เกิดขึ้นทันทีที่ผู้ใช้โพสต์ข้อความ
Multilingual Seamlessness: รองรับการทำงานแบบ Cross-lingual ที่เข้าใจทั้งภาษาไทย อังกฤษ และการพิมพ์สลับภาษา (Thai-English Code-switching) ในประโยคเดียว
Scalable MLOps Pipeline: ระบบมีโครงสร้างที่รองรับการทำ Model Monitoring, Logging และ Automated Retraining เมื่อประสิทธิภาพของโมเดลเริ่มลดลง
6.4 ML Goal
Thai Linguistic Robustness: สร้างโมเดลที่สามารถจัดการกับความซับซ้อนของภาษาไทย และมี performance ที่ดี เช่น การตัดคำ (Tokenization), คำสแลง, การสะกดผิดแบบตั้งใจ และการประชดประชัน (Sarcasm)
Optimizing Recall for Toxic Class: มุ่งเน้นการลดค่า False Negative ให้เหลือน้อยที่สุด เนื่องจากมีผลกระทบต่อความปลอดภัยสูงกว่า โดยยอมรับ trade-off ด้าน Precision ในระดับที่ไม่กระทบต่อประสบการณ์ผู้ใช้มากเกินไป
Drift & Degradation Detection: พัฒนาระบบตรวจจับ Data Drift และ Concept Drift เพื่อรับมือกับพฤติกรรมการใช้คำพูดที่เปลี่ยนแปลงไป เช่น คำแสลงหรือรูปแบบการโจมตีใหม่ ๆ ที่เกิดขึ้นตามกระแสสังคม

7. Project Scoping / Constraints
7.1.Scope
โครงการมุ่งเน้นการพัฒนา Text-based Toxicity Classification System สำหรับข้อความภาษาไทยและอังกฤษ
รองรับเฉพาะ ข้อความ (text) ไม่ครอบคลุมสื่อประเภทภาพ วิดีโอ หรือเสียง
ใช้ Machine Learning / NLP models สำหรับการจำแนก toxic / non-toxic
ระบบทำงานในระดับ prototype / proof-of-concept ไม่ใช่ production-scale big data system

10. Business Metric Alignment
● Reduction in User Reports: ระบบช่วยคัดกรองคอมเมนต์ที่เป็นพิษตั้งแต่ต้นทาง ส่งผลให้จำนวนการรายงาน (user report) จากผู้ใช้ลดลง และช่วยรักษาคุณภาพของพื้นที่การสนทนาในแพลตฟอร์ม
● Moderator Workload Reduction: การใช้ระบบอัตโนมัติช่วยลดภาระงานของทีม moderator โดยคอมเมนต์ส่วนใหญ่สามารถถูกจัดการได้โดยโมเดล และเหลือเฉพาะกรณีที่มีความไม่แน่ชัดให้มนุษย์ตรวจสอบ
● Operational Cost Reduction: ลดค่าใช้จ่ายด้านแรงงานมนุษย์ในการตรวจสอบเนื้อหาปริมาณมาก และเพิ่มประสิทธิภาพในการจัดการคอมเมนต์ในภาพรวม
● Platform Trust & Brand Safety: การลด toxic content ช่วยเพิ่มความน่าเชื่อถือและความปลอดภัยของแพลตฟอร์มในระยะยาว ลดความเสี่ยงด้านภาพลักษณ์จากเนื้อหาที่ไม่เหมาะสม
● ML Metrics Supporting Business Decisions: ตัวชี้วัดของโมเดล เช่น toxic rate, confidence score และเวลาในการตอบสนองของระบบ ถูกนำมาใช้เป็นข้อมูลสนับสนุนการตัดสินใจของผู้ดูแลแพลตฟอร์ม


11. Key Assumptions & Risks
11.1 Key Assumptions
● ชุดข้อมูลสาธารณะที่ใช้มีความเหมาะสมเพียงพอสำหรับการฝึกโมเดลตรวจจับข้อความที่เป็นพิษในภาษาไทยและภาษาอังกฤษในระดับ prototype
 ● รูปแบบการใช้ภาษาและคำสแลงไม่เปลี่ยนแปลงอย่างรวดเร็วจนเกินขอบเขตของระยะเวลาการพัฒนาโครงการ
 ● ระบบถูกใช้เป็นเครื่องมือช่วยคัดกรองและสนับสนุนการตัดสินใจ ไม่ได้ใช้แทนการตัดสินของมนุษย์ทั้งหมด
 ● ปริมาณข้อมูลและจำนวน request อยู่ในระดับที่สอดคล้องกับข้อจำกัดด้านทรัพยากรของโครงการ
11.2 Risks
● Language & Concept Drift
 การเกิดคำสแลงใหม่หรือรูปแบบการประชดประชัน อาจทำให้ประสิทธิภาพของโมเดลลดลงหากไม่มีการปรับปรุงหรือ retrain อย่างสม่ำเสมอ
● Misclassification Risk
 โมเดลอาจจัดประเภทข้อความผิดพลาด เช่น การ block ข้อความที่ไม่เป็นพิษ หรือปล่อย toxic content หลุดรอด ซึ่งส่งผลต่อประสบการณ์ผู้ใช้และความเชื่อมั่นในระบบ
● Over-reliance on Automation
 หากพึ่งพาระบบอัตโนมัติมากเกินไปโดยไม่มี human-in-the-loop อาจนำไปสู่การตัดสินที่ไม่เหมาะสมในบางกรณี
● Scalability Limitation
 ระบบถูกออกแบบในระดับ prototype หากมีการใช้งานเพิ่มขึ้นอย่างรวดเร็ว อาจต้องปรับโครงสร้างระบบเพิ่มเติมเพื่อรองรับในอนาคต
