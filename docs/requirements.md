# Term Project Presentation & Submission Guidelines:
## 1. Presentation Format & Procedure
● Each group will have 30 minutes total, consisting of:
o 20 minutes for presentation and live demonstration
o 10 minutes for Q&A
● Presentations will be recorded via Zoom (link available on MCV) for instructors to review
later.
● All groups must arrive at least 15–20 minutes early and be prepared to present ahead of
schedule if the previous group finishes early.
● Slides should contain all required content and serve as the final deliverable.
● Diagrams must be clearly explained during the presentation. Explanatory text in slides is
optional unless necessary.
● No separate written report is required.
## 2. Term Project Requirements
The term project requires student groups to design, implement, and demonstrate a complete
Machine Learning–enabled software system that addresses a real-world problem. The project should
reflect end-to-end system thinking, integrating concepts from software engineering, machine learning
systems, and MLOps covered throughout the course.
The project is divided into two main parts:
(1) System Architecture Documentation and
(2) System Implementation and Live Demonstration.
### Part 1: System Architecture Overview
Students must document the overall system architecture using established software architecture
modeling techniques.
Requirements: Describe the system architecture using the C4 Model, covering:
1. Context Diagram – system scope, users, and external systems
2. Container Diagram – major system components and technologies
3. Component Diagram (ML component only) – internal structure of key containers
4. Code-Level Diagram (ML component only) – important implementation structures
The architecture description should clearly explain design decisions and trade-offs, particularly those
related to Machine Learning integration.

### Part 2: System Implementation & Demonstration
Student groups must demonstrate a working system and explain how the architecture is realized in
practice. All demonstrations must be conducted live; recorded videos are not permitted.
The demonstrated system must include the following elements:

1. Use Case & User Interaction
• At least one real-world ML use case
• Basic user access control or authentication
• Live demonstration of a front-end user interface
2. Data & Experiment Management
• A clear data management pipeline
• Basic data versioning or dataset tracking
• Reproducible ML experiments with more than one model run
3. Model Evaluation
• Clear evaluation metrics appropriate to the problem
• Basic analysis of model robustness or bias (when applicable)
• Discussion of model limitations
4. Machine Learning System Design
• Overview of the ML system architecture
• Clear separation between data processing, training, and inference
• Explanation of how ML components connect to the software system
5. MLOps & Deployment
• A working model deployment setup
• Use of basic automation or CI/CD for ML components
• Explanation of how the model can be updated or retrained
6. Testing & Maintainability
• Basic testing for data processing or model pipelines
• Description of debugging approaches used during development
• Identification of technical debt and improvement ideas
7. Monitoring
• Simple monitoring of model performance or input data
• Demonstration of data drift or performance change
• Basic strategy for handling model degradation
8. Process and Teamwork
• Description of the development process used by the team
• Clear division of roles within the group
• Reflection on collaboration challenges
9. Responsible Use of Machine Learning
• Consideration of fairness or explainability where relevant
• Awareness of privacy or ethical concerns
• Clear communication of system limitations
